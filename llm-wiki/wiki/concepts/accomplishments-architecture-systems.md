## Architecture and API design

- Defined a cross-platform SDK architecture for PERS devices: ANSI C and predictable-memory requirements, platform-agnostic capability libraries, platform-specific adapters, stable public headers, versioned static or dynamic library artifacts, and future-device platform-abstraction requirements intended to reduce migration effort across wearable generations. [2025-08-30-cross-platform-sdk-modularization-pers-devices](../../raw/brag/2025-08-30-cross-platform-sdk-modularization-pers-devices.md)
- Split a device capability SDK along the organizational boundary — a company-owned application process and a manufacturer-owned service process exposing modem, audio and buttons — connected by the open-source **LCM (Lightweight Communications and Marshalling)** publish/subscribe library over three named channels, with the ODM-facing C header marked in the source as distributed outside the company. [2025-01-16-ccfphone-r5-device-lcm-odm-integration](../../raw/brag/2025-01-16-ccfphone-r5-device-lcm-odm-integration.md)
- Reframed manufacturer collaboration from writing specifications to shipping libraries — "an SDK is a way to inject our own code into the ODM's process" — and set the asymmetric binary policy that follows: manufacturers link dynamic shared objects so behaviour can be upgraded without recompiling their code, in-house code links static libraries, grounded in a Qualcomm/Skyhook integration where exactly that saved a deployment. [2025-08-30-cross-platform-sdk-modularization-pers-devices](../../raw/brag/2025-08-30-cross-platform-sdk-modularization-pers-devices.md)
- Ran a priced build-versus-buy evaluation against a commercial real-time embedded framework combining Active Objects with hierarchical state machines, then built the narrower state machine in-house in ANSI C — having first argued from device scenarios that flat state machines grow exponentially and hierarchy is therefore a requirement. [2024-05-08-ccf-capability-framework-lcm-open-source](../../raw/brag/2024-05-08-ccf-capability-framework-lcm-open-source.md)
- Evaluated Qualcomm/Skyhook Device Observability as a fleet-scale telemetry and diagnostics platform: validated metric quality and semantics, assessed Datadog overlap, cellular reporting cost, OEM dependencies and vendor lock-in, obtained pricing, and built the technical business case for leadership. [2026-01-01-qualcomm-device-observability-evaluation](../../raw/brag/2026-01-01-qualcomm-device-observability-evaluation.md)
- Established device identity as an architectural prerequisite for observability: coordinated firmware, operating-system, SDK and vendor stakeholders around the gap between Qualcomm SoC identity and product OEM identity, and drove the issue toward a supportable implementation direction. [2025-05-01-qualcomm-skyhook-device-identity](../../raw/brag/2025-05-01-qualcomm-skyhook-device-identity.md)
- Connected observability-capable device configurations to Qualcomm's intended CES showcase, making production Lively hardware available for a partner demonstration rather than treating technical integration as an internal-only outcome. [2025-12-01-qualcomm-ces-aware-showcase](../../raw/brag/2025-12-01-qualcomm-ces-aware-showcase.md)

## Networking and transport

The device-side and fleet-side networking record, gathered here because it was previously
spread across *Cloud and distributed systems*, *Embedded*, *Operational excellence* and
*Battery, power and cost of operation* — and a tailored variant could not be drafted from
four half-views. The domain read as a problem space rather than an inventory:
[four problems, four solutions](four-problems.md) § *Networking*.

- Designed and singlehandedly implemented a cross-platform TCP/IP daemon (2004–2005): accept loop, hand-designed wire protocol, authentication, concurrent isolated jobs, progress over the wire, and survival of a client vanishing mid-job — on Windows, Linux and Solaris, before `std::thread`, with one set of shared sources building both ends so the protocol could not drift. [2004-01-01-spm-client-server-tcpip-daemon](../../raw/brag/2004-01-01-spm-client-server-tcpip-daemon.md)
- Grounded that capability: learned network programming from W. Richard Stevens' *UNIX Network Programming*, brought from the U.S. by a Salford colleague; network *engineering* understanding comes largely from Russ White, whose problem-first framing the owner now uses as a working checklist. Includes the owner's deliberate position that never having specialized is an asset — no inherited dogma — alongside the honest gap: no routing-protocol or switch-configuration practice. [2026-09-20-network-programming-foundations-and-mentors](../../raw/brag/2026-09-20-network-programming-foundations-and-mentors.md)
- Corrected callback ownership on the early failure paths of a shared asynchronous HTTP transport (Boost.Beast over a TCP/TLS socket abstraction with asynchronous resolution, SNI, peer and hostname verification, timer-backed TLS shutdown), where an error branch invoked a moved-from callable instead of the owning object. [2025-12-07-http-transfer-callback-ownership](../../raw/brag/2025-12-07-http-transfer-callback-ownership.md)
- Reasoned explicitly about a connected device whose fault reporting cannot assume a healthy network: fire-and-forget HTTPS reporting returns no delivery result, so a quiet dashboard is not proof of a healthy device; local failure, failed report and lost channel are distinguished because they demand different operational conclusions; repeat reports are deduplicated to bound traffic on a metered link. [2025-12-07-http-transfer-callback-ownership](../../raw/brag/2025-12-07-http-transfer-callback-ownership.md)
- Implemented a reduced-activity cellular MQTT keep-alive mode by separating the periodic schedule from the optional work it dispatches, gating at component boundaries rather than one global flag, consolidating shared sync configuration, and keeping the file-descriptor health check ahead of the suppression. [2026-07-29-cellular-mqtt-traffic-scheduling](../../raw/brag/2026-07-29-cellular-mqtt-traffic-scheduling.md)
- Operates a device that degrades rather than disappears: when the TCP/IP data path is broken a separate, narrower SMS command path keeps the device in communication, so an unavailable broker session is not an unreachable device. [2026-07-29-cellular-mqtt-traffic-scheduling](../../raw/brag/2026-07-29-cellular-mqtt-traffic-scheduling.md)
- Took a capability SDK onto production-class hardware as two processes talking over LCM (Lightweight Communications and Marshalling) on UDP multicast — three named channels for commands, events and cross-boundary log records, JSON payloads — chosen over a bespoke socket protocol because any process can subscribe and watch the conversation, which is what the GoogleTest node does. The non-TCP leg of the record. [2025-01-16-ccfphone-r5-device-lcm-odm-integration](../../raw/brag/2025-01-16-ccfphone-r5-device-lcm-odm-integration.md)
- Argued LCM's type-specification language as the answer to manual, error-prone marshalling — the owner's framing is *connascence of type* — and proposed that the existing signal buses could be rewritten on it, while conceding MQTT's quality-of-service and broker features would be the larger effort. [2024-05-08-ccf-capability-framework-lcm-open-source](../../raw/brag/2024-05-08-ccf-capability-framework-lcm-open-source.md)
- Translated cellular radio quality and service state into tested device behaviour (RSRP, RSSI, RSRQ, SNR against their own thresholds), while keeping the boundary explicit: a low-signal indication is not an end-to-end reachability test, and voice service, packet data, TCP, TLS and broker health are five different observations. [2023-04-06-cellular-radio-quality-service-indication](../../raw/brag/2023-04-06-cellular-radio-quality-service-indication.md)
- Joined carrier operations data, device telemetry and warehouse events on IMEI to find devices consuming cellular data far outside any plausible pattern, validated detection against a deliberately built rogue device, got the threshold agreed before an incident, published the runbook, and found a real unit shortly after. Bytes are a direct operating cost on a company-owned MVNO. [2024-01-04-cellular-cost-rogue-device-detection](../../raw/brag/2024-01-04-cellular-cost-rogue-device-detection.md)
- Scheduled location reporting in units of MQTT keep-alive intervals so position rides network wake-ups the device was already making — the point where the transport, the battery and the location domain meet. [2026-07-29-cellular-mqtt-traffic-scheduling](../../raw/brag/2026-07-29-cellular-mqtt-traffic-scheduling.md)
